# 共享契约包

状态：**已落地首轮**（2026-09-25）。本页描述根工作区 `packages/` 下三个契约包的内容、接入点与验证方式。
它们对应[目标架构](/architecture/target-architecture)第 6 节的模块归属，
是迁移顺序中"抽出共享契约"这一步的实际产物。

## 包与职责

| 包 | 职责 | 主要消费方 |
| --- | --- | --- |
| [`@lumesync/classroom-protocol`](https://github.com/yc004/SyncClassroom/blob/main/packages/classroom-protocol/README.md) | 协议版本与协商、角色矩阵、入站/出站事件表、HTTP 路由授权表、消息信封、课堂快照、入站守卫；教室中继的配对/租约/状态机/队列契约；短期会话凭证签发与校验 | 教师服务、教室 Hub、教师页面、学生页面 |
| [`@lumesync/course-format`](https://github.com/yc004/SyncClassroom/blob/main/packages/course-format/README.md) | `.lume` manifest schema 与校验、ZIP 读写与安全限制、内容 hash、旧脚本课件迁移 | 教师服务（课程扫描、导入）、教室 Hub（课件暂存校验）、编辑器与播放器（后续接入） |
| [`@lumesync/native-contract`](https://github.com/yc004/SyncClassroom/blob/main/packages/native-contract/README.md) | 原生桥消息封装与回执、按角色的动作能力清单、教师/学生桥类型 | 两端页面、C++ 原生壳（对照校验）、Electron preload |
| [`@lumesync/teacher-platform`](https://github.com/yc004/SyncClassroom/blob/main/packages/teacher-platform/README.md) | 教师端平台能力接口（文件、导入导出、提交目录、日志、窗口、全屏、受保护会话凭证）与 WebView2 / Electron 适配器 | 教师 React UI、现有 Windows 壳、Electron 桌面壳（`apps/teacher/desktop`） |

## 本轮修掉的两个实际缺陷

1. **会话引导被授权中间件挡住。** `apiRouter` 挂在 `/api` 上并带 host 授权中间件，
   `/api/session/bootstrap` 又由 `server/index.js` 处理，于是"写请求一律要求 host"的兜底规则
   先返回 403：viewer 与 host 都领不到凭证。现在路由表把该路径标为 `bootstrap`，
   由处理器自己执行"本机 + `X-LumeSync-Host-Token`"或"签发 viewer 凭证"的规则。
   回归用例：`repos/teacher/server/tests/session-bootstrap.test.js`。
2. **教师页面的凭证包装器没有装到全局。** 原来只在打包后的 IIFE 里遮蔽 `fetch`，
   内联脚本与课件运行时拿到的仍是原生 `fetch`；构建产物过期时页面会在"路由要求凭证"下静默失败。
   现在同时设置 `window.__LumeSyncApiFetch` 与 `window.fetch`。

## 教室中继契约（`src/relay/`）

[跨平台教师端与中继模式](/architecture/teacher-cross-platform-relay)要求的能力已先行固化为纯逻辑契约，
Hub 只负责接传输、持久化与凭证签发：

| 模块 | 内容 |
| --- | --- |
| `src/relay/pairing.js` | 8 位数字验证码（CSPRNG、拒绝采样）、3 分钟有效期、每次请求 5 次尝试、绑定教室+请求+设备公钥；`createPairingProof` / `verifyPairingProof` 用验证码做 HMAC 握手证明（必须在 TLS 之上）；对外描述与屏幕描述严格分离，验证码不会进日志或发现报文 |
| `src/relay/lease.js` | 单教室单租约、`acquire/renew/release/revoke`、`epoch` 在交接后继续递增、超时进入 `awaiting-teacher`；`authorizeCommand` 校验每条命令的 `leaseId + epoch` |
| `src/relay/state.js` | 固定机状态机 `disabled → idle → pairing → paired/teaching`、`error`；发现 TXT 只含教室名、设备 ID、协议版本、端口与空闲/占用，没有屏幕时明确拒绝开启而非无验证码降级 |
| `src/relay/queue.js` | 提交转发队列（容量满时返回 `queue_full` 而不是静默丢弃；`submission:delivered` 之后才释放副本）与课件暂存缓存（按 `courseHash`、发布新版本时旧版本继续保留、当前版本不因过期被清理） |
| `src/relay/events.js` | `teacher:pair.*`、`teacher:lease.*`、`course:stage/publish`、`classroom:command`、`submission:delivered` 及对应出站事件的 schema 与角色要求 |

事件表带 `scope`：`classroom` 为直接模式事件，`relay` 为固定机 Hub 事件。
`createInboundGuard({ scopes })` 与 `authorizeEvent(..., { scopes })` 让直接模式的教师服务只接受
`classroom` 事件，Hub 才接受两类——避免出现「声明了但没有处理器」的静默路径。

## 验证方式

```bash
pnpm run test:contracts        # 三个契约包的用例
pnpm run test:teacher-server   # 教师服务用例（含协议握手、引导回归与授权回归）
pnpm run test:hub              # 教室 Hub（真实 Express + Socket.IO + course-format 课件）
pnpm run test:session-agent    # 教师端会话代理（单元 + 驱动真实 Hub 的集成）
pnpm run test:teacher-desktop  # Electron 桌面壳的页面来源与课件路径守卫
pnpm run test                  # 以上全部，外加学生课堂 UI 构建产物
```

契约包测试包括：ESM/CJS 导出一致性、事件表角色矩阵与当前处理器行为一致、
路由授权表与既有 `http-auth` 断言一致、ZIP 路径/大小/压缩比限制、迁移可复现性，
以及 C++ 壳动作分派与能力清单的一致性对照。

教师服务侧另有两组面向真实客户端的回归用例：`client-payload-contract.test.js`
按教师页/学生页/Core 的真实调用点校验 payload 不被契约误伤；
`api-authorization.test.js` 用真实 HTTP 请求确认大小写、尾斜杠、HEAD 与非标准方法
都不能绕过 host 授权。
