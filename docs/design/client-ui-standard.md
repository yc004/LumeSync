# LumeSync 客户端 UI 标准

版本：1.0（2026-09-28）。**规范性文件**，适用于教师端 Windows WebView2/Electron、学生课堂页及本机管理页、课件编辑器、教室固定机投影页。文档站与下载站在修改界面时也采用本规范的视觉基础、文案和无障碍规则。当前代码尚未全部达标；差距与迁移顺序见[UI 迁移清单](ui-migration.md)。

本规范借鉴 [Apple macOS HIG](https://developer.apple.com/design/human-interface-guidelines/designing-for-macos/)、[Microsoft Fluent 2 原则](https://fluent2.microsoft.design/design-principles)、[Fluent 2 设计 token](https://fluent2.microsoft.design/design-tokens)、[Material 3 基础](https://m3.material.io/foundations/)与 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)。以下具体数值、布局和产品流程是 **LumeSync 的设计决策**，不是这些规范对本产品的逐项规定。平台原生控件、菜单、窗口行为优先遵循对应系统约定；跨平台语义、品牌和任务流程保持一致。

## 1. 设计目标与优先级

1. **课堂不中断。** 当前课程、连接状态、剩余操作时间和提交结果始终可辨；错误要给恢复动作。实时课堂操作优先于装饰。
2. **每屏一个主要任务。** 用标题、状态、主要操作和次要操作建立层级；不要把所有功能挤在同一个工具栏。
3. **先呈现事实，再呈现控制。** “已连接 / 正在重连 / 未提交 / 已保存”均来自真实状态。不能只用颜色、图标或动画暗示。
4. **桌面熟悉、跨端一致。** 教师和编辑器支持窗口缩放、菜单、快捷键和精确指针；学生页面突出课件与互动；固定机投影重视远距离阅读。
5. **离线和故障可理解。** 所有客户端均须有空白、加载、离线、重试、权限不足和操作成功状态。

规范词：**必须**是合并门禁；**应**允许有理由的例外。例外需在变更说明中给出使用场景、替代设计、无障碍验证和迁移期限，并记入[迁移清单](ui-migration.md)。已有页面未迁移时按清单管理；新页面及实质改版页面必须达标。

## 2. 跨客户端设计基础

**唯一 token 来源**：[`packages/ui-foundations/tokens.css`](../../packages/ui-foundations/tokens.css)。CSS、Tailwind 映射和桌面宿主主题均从语义 token 派生；不得直接用 `blue-500`、裸十六进制色值或临时字号作为新页面的设计决策。用户课件内容属于独立画布，不强制套用应用壳 token；课件外的导航、控制和反馈必须使用本规范。

| 语义 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| 画布 / 表面 | `#F6F8FC` / `#FFFFFF` | `#101725` / `#1B2638` | 应用背景和内容容器 |
| 正文 / 次要文字 | `#172033` / `#526176` | `#F4F7FD` / `#B8C6DB` | 正文、辅助信息；重要状态不用次要文字 |
| 主操作 / 主操作文字 | `#2457C5` / 白色 | `#A5C4FF` / `#101725` | 每个任务区域至多一个高强调操作 |
| 危险 / 成功 / 提醒 | `#B42332` / `#12633C` / `#8A4B00` | `#FFB4B8` / `#8DE0AD` / `#FFD76E` | 与文字和图标一起传达含义 |
| 控件边界 / 焦点 | `#8394AB` / `#155EEF` | `#879AB5` / `#A5C4FF` | 可操作边界和键盘焦点 |

浅色的正文、次要文字、主按钮文字及控制边界与相邻白色表面的计算对比分别约为 16.3、6.3、6.5 和 3.1:1；深色 token 在深色表面上仍需逐组件复核。装饰分隔线可以更浅，但不能单独承载控件边界或状态。Web 内容以 **WCAG 2.2 AA** 为门槛：普通文字至少 4.5:1，大字至少 3:1，必要的非文字信息和控件边界至少 3:1；对比度要在实际叠层、图片和所有交互状态下重新测量。[WCAG 对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum)、[非文字对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)。

- **字族**：优先系统 UI 字体，中文回退 `PingFang SC`、`Microsoft YaHei UI`、`Noto Sans CJK SC`；代码/编号使用系统等宽字体。界面不能依赖网络字体。
- **字级**：说明 12、正文 14、重点正文 16、区域标题 20、显示标题 32 CSS px；正文行高 1.5。12px 只用于非关键说明，课堂状态、错误和主要操作不得低于 14px。投影另见第 3 节。
- **间距**：4、8、12、16、24、32、48px；同一语义关系保持同一间距，区块之间的距离应明显大于区块内部。控件圆角 8、面板 12、对话框 16px。阴影只表达层级，不作为控件可辨识的唯一线索。[Fluent 布局原则](https://fluent2.microsoft.design/layout)。
- **图标**：选用同一家族、同一线宽；图标按钮必须有可访问名称和可见的悬停/焦点提示。常用动作优先“图标＋文字”，不得用图标代替不熟悉的课堂术语。
- **密度**：教师/编辑器允许信息密集，但不能低于可读字号与点击目标门槛；学生和投影界面优先留白与大目标。平台原生菜单、窗口控件、文件对话框、滚动条和快捷键遵循系统习惯。

## 3. 各客户端的界面骨架

| 客户端 | 主任务与默认信息层级 | 页面结构 | 适配与特殊约束 |
| --- | --- | --- | --- |
| 教师端 `apps/teacher/ui` | 当前班级/课程 → 连接与授课状态 → 翻页/结束等课堂控制 → 学生互动与提交 | 顶部上下文与状态；中央课件舞台；可收起的学生/互动侧栏；次要设置在独立面板 | 窗口 1050×680 至全屏均可操作；窄窗收起次要栏，课堂状态和结束/恢复入口不被遮挡；Windows 和 macOS 保留各自窗口习惯 |
| 学生课堂 `apps/student/ui/classroom` | 课件 → 当前互动题/提交 → 网络与同步状态 | 课件占主区域；互动面板按任务出现；连接/提交状态固定可见但不盖住内容 | 1024×600、1366×768、1920×1080 检查；投影和课件缩放不裁切关键内容；离线时说明可继续看的内容与待重发操作 |
| 学生本机管理 `apps/student/ui/student-host` | 设备连接/服务状态 → 设置或修复 → 退出 | 单列任务流程；设置分组；危险操作单独区域 | 800×600 起可用；密码、网络、服务失败给具体重试步骤；退出/重置需明确影响 |
| 课件编辑器 `apps/editor/app/ui` | 文件与保存状态 → 页面树 → 编辑画布 → 属性/资源/Agent → 诊断与预览 | 顶部文件与主操作；左树、中画布、右检查器；可收起 Agent/诊断 | 1120×720 至大屏；窄窗折叠检查器而不压缩 16:9 画布；保存与构建状态持续可见；Agent 候选须与正式草稿明显区分 |
| 固定机投影 `apps/classroom-hub/projector` | 教室名与模式 → 配对码/课堂状态 → 少量操作提示 | 全屏深色、高对比、居中大字；只读信息逐层分组 | 1920×1080 和 1280×720，3–5 米可读；核心码至少 64px、状态文字至少 28px；验证码有过期提示且不得隐藏于颜色变化中 |

教师课堂与学生课件的内容层允许全屏，但应用控制层应保留可恢复的入口。固定机投影没有交互时不要伪装成按钮。文档站和下载站采用单一主导航、清晰页面标题、当前状态/版本与下载资产来源；它们不继承课堂端的大屏密度。

## 4. 必备组件与行为

| 组件/场景 | 必须实现的行为 |
| --- | --- |
| 按钮与链接 | 按钮触发动作，链接负责导航；每个任务区只突出一个主操作。禁用时说明原因；异步动作显示进行中、禁止重复提交，结束后给结果。危险操作用明确动词和对象，不用“确定”。[Fluent 按钮指南](https://fluent2.microsoft.design/components/web/react/core/button/usage) |
| 输入与表单 | 可见标签、格式提示、就地错误、保留用户输入；校验错误说明如何修正。密码可显示/隐藏，不能仅靠 placeholder 说明。保存后反馈已生效的设置。 |
| 导航/侧栏/标签 | 当前项有文字和形状/位置线索；键盘顺序与视觉顺序一致；不因面板切换丢失当前课程、页面或未保存内容。 |
| 弹窗与菜单 | 仅用于必须立即决策或危险动作；焦点进入后留在弹窗内，关闭返回触发点；Escape 关闭非阻断弹窗。长流程用页面/面板，避免弹窗叠弹窗。 |
| 空白、加载、错误 | 空白说“缺什么、可做什么”；加载说明任务和是否可取消；错误说“发生了什么、影响范围、下一步”。网络失败区分“未发送”“待重试”“已确认”，禁止用成功样式替代服务端确认。 |
| 实时状态 | 在线/重连/离线、租约/授课、课件发布、提交落盘均需文字＋图标或形状；重要变化用非阻断状态区公告，必要时给时间戳与重试/刷新。 |
| 拖放/排序 | 提供键盘或按钮等效操作、明确拖放目标和撤销。不能让座位管理、页面排序只能用鼠标。 |
| Agent 生成 | 标记“模型生成的候选”；展示来源/将改动的范围/诊断；接受和放弃分开，接受前不得覆盖正式内容。涉及发送材料时先展示范围并取得用户操作。 |

关键课堂动作的反馈时序：本地即时展示“正在发送” → 服务端确认后展示“已生效”；超时显示“结果未确认”并提供重试或查询，不得推断成功。可撤销的破坏性操作优先撤销；无法撤销时确认文案写明对象与后果。跨端同一动作使用同一中文术语，例如“发布课件”“结束授课”“提交作业”，避免同屏混用“上传/同步/推送”指同一动作。

## 5. 无障碍、动效与响应式门禁

- **键盘**：所有可执行功能均可用键盘完成；保留可见 `:focus-visible` 焦点，推荐 2px 实线＋与背景至少 3:1 的变化；绝不全局 `outline: none`。[WCAG 焦点可见](https://www.w3.org/TR/WCAG22/#focus-visible)。
- **目标尺寸**：普通网页目标至少 24×24 CSS px 或满足 WCAG 间距例外；本项目常用按钮/行目标应达到 36×36，学生触控操作应达到 44×44。紧凑桌面表格例外须有同页等效入口。[WCAG 目标尺寸](https://www.w3.org/TR/WCAG22/#target-size-minimum)。
- **语义**：真实 HTML 按钮/表单/标题；图标按钮有名称；状态变化按重要性用 `aria-live`，避免整个应用根节点成为实时播报区。错误与字段关联；弹窗有标题与焦点管理。
- **放大与重排**：文字可放大到 200% 而不丢功能；窗口缩小时面板重排/折叠，不用把断点强制设为同一宽度，也不隐藏所有滚动条。课程画布可按内容比例缩放，但界面控制和反馈不随画布缩到不可读。
- **动效**：仅用于方向、状态和因果；常规过渡 120–200ms，不做无意义循环。遵循 `prefers-reduced-motion: reduce`，停止非必要位移与闪烁；固定机验证码提示的闪动也要有静态替代。[W3C 减少动效技术](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)。
- **主题**：支持浅色、深色和系统高对比模式；固定机可固定深色，但必须维持高对比。任何新状态色在各主题和禁用/悬停/选中/焦点状态下验证。

## 6. Agent 设计与实现交付门禁

每次改 UI 时，Agent 必须先阅读本页、[迁移清单](ui-migration.md)与目标客户端现有实现，然后在变更描述中交付：

1. **任务与结构**：目标用户、主任务、信息层级、涉及的页面/组件；如改动既有流程，说明入口与返回路径。
2. **状态矩阵**：默认、空白、加载、成功、错误、离线/重连、无权限、禁用，以及需要保留的草稿或课堂状态。可用“不适用”但须解释。
3. **视觉映射**：所用语义 token、字号、间距、控件变体；新增 token 必须先改 `tokens.css` 和本规范，并验证对比度。
4. **输入方式与布局**：鼠标、键盘、触控适用性；焦点顺序、可访问名称；第 3 节对应尺寸的截图或现场检查记录，包含文字放大与窗口缩小。
5. **验证**：至少完成相关客户端的现有测试与交互检查；检查浅/深主题、减少动效、错误恢复和真实数据长文本。未完成项写进迁移清单，不能称“符合规范”。

代码评审以这些证据核对**新页面和实质改版页面**。若仅修改文案或修复局部逻辑，至少保持原界面可用且不新增违反项。设计稿是意图描述，具体实现须与真实客户端状态、平台能力和本规范一致。
